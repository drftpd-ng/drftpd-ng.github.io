One FTP site.
Every server you own.

DrFTPD is a distributed FTP daemon. A single master speaks FTP and keeps the filesystem; any number of transfer slaves store the files and move the bytes. Your users see one site, with the bandwidth and disks of all of them.

How it works

    
The master thinks. The slaves move the bytes.

    
Most FTP servers store files on the machine they run on. DrFTPD splits that job in two, so one site can span many servers while users keep the FTP client they already know.


    

      

        

        
01 / client

        
Users connect as usual

        
Any FTP client works, FXP included. Passive mode needs PRET, which the major clients already support.

      

      

        

        
02 / master

        
The master holds the map

        
It handles the FTP control connection, users, permissions and the virtual filesystem: which file lives on which slave, plus its size, owner and dates.

      

      

        

        
03 / slaves

        
Slaves store and transfer

        
Slaves are kept thin: they know nothing about users or the FTP protocol. They report their files on startup and run the master's instructions.

      

    


    

      
10 × 1 Gbit

      
Merge ten 1 Gbit servers and you get 10 Gbit of aggregate bandwidth; a single transfer still tops out at the speed of the slave serving it. A file can live on several slaves for redundancy and extra throughput.

    

  






  

    
Features

    
Built for scene-style sites, from the start.

    
Race stats, SFV checking, nukes, an IRC bot, requests, trials. Most of it ships in the box as plugins you turn on in configuration.


    

      

        

        
Zipscript and race stats

        
SFV and CRC checking on upload, ZIP integrity checks, incomplete markers, and race leaders announced as files land on the slaves.

IRC sitebot

        
A built-in bot announces races, new releases and nukes, and answers commands on IRC. FiSH (Blowfish) encryption is supported.

        sitebotblowfish
      

      

        

        
TLS everywhere

        
TLS on FTP control and data connections, and SSL between the master and its slaves using a key generated with genkey.

      

      

        

        
Redundancy and jobs

        
Keep copies on several slaves, mirror sections, archive old releases and move files between slaves with background jobs.

      

      

        

        
Site operations

        
Nukes and autonuke, dupe checking, requests, trials, traffic statistics, auto free space, and SITE commands for day-to-day admin.

      

      

        

        
Pluggable by design

        
Features are Maven modules split into master and slave sides. Write your own, or switch off the ones you don't use.

Quick start

      
Up and racing in minutes.

      
Build from source with Maven, start the master, then point slaves at it. Full configuration lives in the .dist files.

      

        
masterJDK 17, Apache Maven, Git

        
slaveJava 17 runtime, plus mediainfo CLI for media checks

        
clientAny FTP client; PRET support for passive mode

      

    

    

      

        
        
        
        
      

      
$ git clone https://github.com/drftpd-ng/drftpd.git
$ cd drftpd
$ git checkout tags/4.0.11
$ mvn validate
$ mvn install
# the runtime/ directory now holds master and slave

      
# copy the .dist files you change to .conf (at least master.conf)
$ ./genkey.sh            # optional: SSL between master and slaves
$ ./master.sh
# connect to 127.0.0.1:2121 as drftpd / drftpd, then:
ftp> SITE ADDSLAVE SLAVENAME
ftp> SITE SLAVE SLAVENAME ADDMASK *@IP.MASK

      
# copy slave.conf.dist to slave.conf and set the master address
# optional: copy drftpd.key from the master into config/
$ ./slave.sh
# the slave sends its file list and joins the site

      
! Change the default drftpd login before exposing the server. On Windows use the .bat scripts.
